# Proposal

## Why

现有ImageCaption的CLI与独立批处理已经承担实际数据生产，但阶段产物、排除清单、标注变体和导出缺少统一的数据版本入口，direct CLI也未接入按图片统计的持续进度。用户需要在保留水印裁剪主流程的基础上，加入文字面积过滤、美学与像素策略、短中长描述，以及能显示阶段和阶段内部进度的看板。

## What Changes

- 2026-10-27追加：当前配方仅生成详细长描述；变体集合可配置，旧配方省略时保持三档。版本、标注和审阅结果保存可读生成模型与冻结身份，提供JoyCaption和Huihui Qwen3-VL可选配置及CLI profile选择，其他VLM继续使用兼容API。

- 追加关闭ArtiMuse/DeQA的吞吐试点：保留其余质量阈值，输入和裁后短边512，保留默认裁剪及JoyCaption三档描述；用户允许使用node94空闲GPU，创建新冻结版本并记录网络盘条件、实际裁剪数和端到端耗时。

- 追加Demo提示词透明化：所有system/user/附加规则可见可编辑，模板显式载入，取消输出格式触发的后台拼接；展示待发送及本次实际消息和原生聊天模板。

- 2026-10-26追加：独立caption Demo支持自由JSON与固定分类标签模板，生成后严格解析并明确语义未审核；按用户要求提供带认证的临时公网测试链接，不接入生产版本。

- 2026-10-26追加独立caption试验：在node94部署用户指定Huihui-Qwen3-VL-8B-Instruct-abliterated的Gradio demo，核验同源量化方案并在同卡受控输入下测速；不修改生产流水线或用测速代替语义质量审核。

- 追加用户主动打开的“处理结果”：与所选Workbench版本绑定，只读浏览已校验审阅包中的实际视图、裁剪信息、三档描述、标签和评分；进度与诊断页继续不加载语义内容。显示训练交付登记但不将审阅完成升格为发布。

- 追加网页整理与只读配置展示：主导航收敛为运行看板、运行配置、系统诊断和帮助，按追加要求从主导航移除旧工具但保留历史链接；看板采用阶段列表与单项详情，统一文字及悬浮行为。CLI同步与运行身份绑定的白名单配置摘要，网页仅展示，不编辑配方或控制任务；旧记录缺失保持未知。

- 追加吞吐与模块边界：暂不引入GBC或LangGraph；分离可复用模型配置、阶段绑定、推理后端及有界执行。新增OpenAI兼容图文服务与同模型多端点池，保留本机常驻command；通过阶段内并发向服务端持续合批供给，保持单一结果提交、恢复与版本身份。远程权重修订明确为部署声明，不能冒充本地权重校验。
- 以ImageCaption为运行时产品，CLI为主要执行入口；终端状态与只读网页看板进入第一批交付，共享持久进度来源。
- 修正网页新旧流程入口、运行身份和状态表示：Workbench与旧任务参数分离，刷新及前进后退恢复正确上下文；异步请求不能串运行或图像，缺记录、连接失败和空结果分别说明。
- 区分数据集、处理运行、候选/已发布版本及导出包；版本固定输入、图像视图、策略、模型、标注和结果摘要，支持比较、恢复与增量处理。
- 将水印候选检测与确认分开；裁剪搜索同时满足保留面积、输出尺寸和障碍框约束，保存原图及排除原因。
- 裁剪提供默认开启的严格布尔开关；任何有效视图记录裁剪决策和几何元信息。仅为实际选用视图生成长中短描述，已裁剪样本不重复生成原图描述。
- 将可选的非露骨语义标签接入Workbench，限定姿态、构图、视角、可见度和内容安全大类，保留视图及长描述来源、词表/模型身份和待审核状态；不生成具体性行为细节。
- 新增整图文字区域检测，以最大文字块和区域并集占比过滤主集，裁后复检；不把检测失败当作无文字。
- 记录独立美学/技术画质与像素观测，按版本化策略分为主集、属性监督候选、待复核或不可处理；待复核样本不能自动成为水印负样本。
- 美学和技术画质提供独立执行开关；显式关闭时跳过模型校验、加载与评分，保留关闭状态，并仅按其他已启用规则分流。
- 增加原始文件字节数/像素数门控，参考LLaDA-Image的0.15 byte/pixel，支持配方与CLI调整、关闭、版本冻结和影响预览，保留原图与复核原因；调研已有prompt的开放模型语义标签化方案，模型选择与标签质量验收单独记录。
- 复用现有caption适配与摘要工具，形成视图绑定的长/中/短描述、独立属性和完整条件导出。
- 增加默认关闭且严格为布尔值的`captions.review_candidates`，显式启用后为有效待复核视图生成长/中/短草稿，冻结配置及标注身份，不改变路由、审核结论或训练准入。
- 增加独立的`workbench review-export`审阅交付，包含来源/视图、三档草稿、数值观测、校验和与离线HTML，供用户自行检查；审阅导出不调用训练发布、不写ready，不将未校准结果伪装为训练成品。
- 兼容旧CLI、旧水印策略及历史导出；新能力使用显式新策略，旧产物不原位改写。旧计划已验收项不等于新产品集成已完成。
- 按2026-10-22追加需求逐模块复核合理性，使用真实数据进行不展示语义的处理形式与速度测试；补充分阶段计时、资源采样、恢复时字节重验及四张5090容量分析，区分独占实测、共享环境实测和假设估算。

## Capabilities

2026-10-23追加：依据论文和社区工具的一手资料复核标签、长中短描述与加速路线；改善现有只读看板的首次使用、流程导航、问题定位及诊断导出。复核并减少同权重描述worker的无效重载，保持每变体身份及恢复语义。标签模型部署、四卡调度与真实质量校准须独立验收，不随界面或文献审核自动完成。

同日追加首批审阅结果交付：利用node95 GPU 3可用窗口，在独立目录对已获授权的32张确定性样本运行形式与性能试点，执行资源占用守卫、输入不变校验、模块计时、恢复及评分开关/文件密度门控对照，并同步两仓库代码与规格。助手只查看数值与处理形式，真实图像、caption和OCR由用户在本地审阅包中自行检查。描述质量、裁剪确认及其他门槛仍待校准；本轮不扩大原任务2.5与6.4的验收范围。

### New Capabilities

- `imagecaption-dataset-versions`: 数据集、运行、版本、导出、历史纳管及增量引用。
- `imagecaption-watermark-crops`: 水印候选确认、受约束裁剪及结果复核。
- `imagecaption-text-region-filter`: 整图文字框观测、面积策略和裁后复检。
- `imagecaption-quality-pools`: 质量评分、分类、配方校准与主/辅助/复核分流。
- `imagecaption-caption-variants`: 短中长描述、属性监督、条件组装和导出兼容。
- `imagecaption-cli-progress`: CLI内部计数、断点恢复、终端/网页看板及状态来源。

### Modified Capabilities

无已归档主规格。本change使用产品命名空间；旧`design-image-data-framework`的通用契约与21/70项实施记录保留，其未完成功能不作为本change的已交付能力。

## Impact

规划保存在本DataPipeline仓库并随其同步；目标代码为[lililuya/ImageCaption](https://github.com/lililuya/ImageCaption)的Python CLI/worker、PostgreSQL/API、direct batch适配和现有React进度页。后续实施须在目标仓库的完整checkout中进行，先确认基线与迁移边界，再将对应规格带入目标实施上下文；不将本地审阅缓存当作完整工程，也不直接混用两套数据库表结构。

规划阶段已完成，v0.2及v0.3的实际范围分别见实施记录。默认使用本地硬盘，模型适配依赖单独管理；已获准在独立目录运行模型及真实数据形式测试，不改写远程历史批次。首版不扩展多参考/偏好训练、完整内容管理网页或分布式存储。真实图像、标注、批次路径、日志和模型不入Git；工程依据及公开模型事实见[研究依据](../../../docs/research-evidence.md)。
