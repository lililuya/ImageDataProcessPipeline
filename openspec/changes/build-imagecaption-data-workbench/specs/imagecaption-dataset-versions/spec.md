# Spec Delta

## Purpose

本能力为ImageCaption提供可查询、比较和恢复的数据版本目录，将长期数据集、一次处理运行、固定数据内容及交付格式分开，使CLI批次和历史导出的身份、来源、策略及标注关系可以持续追溯。

## ADDED Requirements

### Requirement: 数据集运行版本与导出身份

系统 SHALL 在创建处理计划时为数据集预留唯一递增版本号，关联运行ID与父版本；同一构建的重试沿用版本号和运行ID并记录新尝试，导出包独立标识其所引用版本及格式配置。

#### Scenario: 构建失败后重试
- **WHEN** 未改变冻结输入和策略的构建失败后恢复
- **THEN** 继续原候选版本，保留失败尝试和结果，版本号不被另一构建复用。

#### Scenario: 并发创建两个版本
- **WHEN** 两个CLI同时基于同一数据集创建版本
- **THEN** 获得不同版本号，分别记录父版本和运行ID，不覆盖成员或进度。

### Requirement: 不可变内容与差异比较

系统 SHALL 固定版本的输入快照、成员、实际图像摘要、视图、策略、模型、标注和审核引用；已发布版本不可原位修改，内容变化产生新版本，并提供新增、移除、视图改变和标注改变的差异及原因。

#### Scenario: 仅更新短描述
- **WHEN** 用户修改已发布数据中一条短描述
- **THEN** 新版本引用新标注且复用未变化图像，旧版仍可读取原短描述，差异明确标为标注变化。

### Requirement: 增量结果复用

系统 SHALL 仅在输入视图摘要、算子、模型、模板和配置身份全部相符时复用阶段结果；阈值变化可重做选择，模型或描述模板变化必须重新计算受影响结果。

#### Scenario: 相同图片更换描述模板
- **WHEN** 图片字节不变但caption模板升级
- **THEN** 旧caption不能因图片SHA相同而自动充当新模板结果，未受影响的像素观测仍可复用。

### Requirement: 历史批次纳管

系统 SHALL 只读导入旧CLI的输入、策略、结果和排除清单，保留原路径关系及历史身份；缺失的输出摘要、模型或标注信息明确为未知，区分仅完成图像准备与可供图文训练的发布。

#### Scenario: 历史批次只有裁剪清单和完成标记
- **WHEN** 历史批次没有可验证的caption绑定
- **THEN** 登记为图像准备产物，不能仅凭完成标记宣布训练数据已发布；补充校验形成新证据而不覆盖历史声明。

### Requirement: 发布校验与存储复用

系统 SHALL 在发布前验证固定成员、来源可用性、实际输出摘要、必需标注、主/辅助用途和关联组划分；复用不变对象，消费者只能读取满足目标格式要求的可用版本。

#### Scenario: 原图与裁剪图被分到训练和验证两侧
- **WHEN** 同源属性样本与主集裁剪样本跨越训练及验证划分
- **THEN** 阻止发布并报告关联冲突，不通过分别放在两个池中绕过检查。

#### Scenario: 已发布文件被外部修改
- **WHEN** 导出或读取时实际摘要与固定引用不符
- **THEN** 报告产物损坏并停止消费，不能静默更新旧版本摘要。
